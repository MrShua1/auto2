Load and use only the `auto` Skill. Execute its `/分集` (`episode_prevideo`) control
mode for this request:

`$ARGUMENTS`

Read references/auto-d-portability-and-materials.md first; it overrides older route,
material-review and delivery-layout defaults below. Install bundled missing tools
instead of bypassing their gates. TSC is Agent-authored under the internal module.
Use the user-selected image route. Physically integrate supplied materials into
relevant assets. Never create delivery preview pages or change requested SEG granularity.

Require an explicit `PROJECT_ROOT` for a new project. First check for user-confirmed
asset records, then always preview the user-requested script portion before generation.
Recursively inventory the root, fully read all candidate scripts, asset manifests and
wardrobe tables, and only list candidate image files without decoding or inspecting
their content. Continue autonomously through
verbatim extraction, canon, segmentation, textual shot execution, full script
coverage, conditionally required `st2` asset generation, aggregate human asset
selection, required sound/reference resolution, TSC handoffs, every final pre-video `prompt.txt`, asset
workbook, fixed episode package, and complete pre-video validation.

For every new project, instantiate and lock Auto's `productionProfile` before shot
planning. Do not inherit genre, period, culture, audience, visual medium, LOOK,
aspect ratio, target model, duration range, timed-phase count or music policy from
another project or example. Existing Auto 2.1 projects resume under their recorded
legacy contract unless the user explicitly requests migration and revalidation.

For a new project, set `videoBackend` to `unselected` unless the user explicitly chose
`libtv` or another backend. An unselected backend, missing LibTV installation, missing
LibTV login or unavailable LibTV schema must not block segmentation, textual shot
execution, backend-neutral TSC prompts or `final_prevideo` completion.

Build a version-level `asset-requirements.json` from the complete script. Do not
inspect or judge image content. Treat only exact files previously confirmed by the
user, with unchanged hashes, as valid; list all other existing images for human review.
Preserve confirmed valid assets unchanged and generate only missing or human-rejected
versions. Build `生图需求全集.xlsx` before generation with one
generation-required version per row. Require `direct_image_run` only when that workbook
contains work that must actually be generated; when all required assets are already
human-approved, its absence is not a blocker. While images generate, build asset-independent
segment files in parallel; final prompts and verified slots wait for asset approval.

Do not ask the user to manually write character or wardrobe appearance text for every
approved version. Derive locks from scripts, bibles, wardrobe tables, manifests and
approved generation prompts. If an approved reference is the sole appearance authority,
use Auto's `reference_preservation` lock without inspecting the image. Ask only when a
required version has neither an approved reference nor sufficient textual evidence.

Persist `auto-state.json` and resume the first unresolved stage when this command is
invoked again for the same project. Pause only for a true hard decision such as an
ambiguous screenplay/episode boundary, rights, an explicit budget conflict, aggregate
human asset selection, or a required reference that cannot be generated or supplied.
After the user resolves that decision, continue the same `/分集` mode automatically.

This command never generates video. Set `videoLimit` and `videoUsed` to `0`, set the
hard stop to `no_video_side_effects`, and do not call `libtv upload`, `libtv node
create`, `libtv node update`, any node run, download, or
`generate-segment-libtv.cjs --run`. Read-only LibTV help/account/project/model-schema
queries are allowed only when `videoBackend: libtv`. Stop after
`validate-prevideo-delivery.cjs` passes and report the verified package path and any
remaining blockers. Do not claim completion from prompt validation or packaging alone.
