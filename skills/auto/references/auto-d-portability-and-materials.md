# Auto D Portability And Supplied Materials

## Hard Gates Remain

An API health check is not a completed production package. If image work exists
and direct_image_run is missing, report the exact missing tool and run the bundled
installation/readiness procedure with user permission. Restart the host and verify
the tool is advertised in the current session. Do not send paid requests through
an improvised API client. A passing offline test proves wiring, not credentials,
balance, live provider success, host registration or user approval.

TSC is a semantic Agent operation using modules/tsc/MODULE.md and its resources.
The Agent writes source-specific prompts then runs the bundled validators. No
external storyboard-generator executable is required. Complete scripts, approved
required assets, causal handoffs, topology and semantic review remain mandatory.
For large projects continue in recorded batches; never equate a file count,
extract-only workspace, successful API test or draft with final delivery.

## Material-In-Frame Contract

At intake, build material-integration.json. Include every supplied visual material,
even when it is excluded with a concrete reason. Each source records sourceId,
sourcePath, sourceSha256, intendedUses, exactTextAuthority, conflicts and reviewStatus.
Every relevant binding records segmentId, shotIds, sourceIds, targetAssetId,
referenceRoles, placement, readableContent, integrationMethod, targetPath,
targetSha256 and humanReview. Integration methods are reference_image_edit or
deterministic_composite. An archive-only binding or blank placeholder does not pass.

When requested by the user, inspect supplied image content for accurate placement
and text conflict detection; this is not permission to invent approval. Notice-board
posts, banner mounting, document handoffs and reading must be visible in the actual
location/prop image, not just a separate folder, Mixed slot or prose suggestion.
Pass original source files as per-job referencePaths and say what each controls:
location geometry, person identity, notice artwork, paper content or layout.
Image references must never change character identity or wardrobe.

Place notices at credible rural anchors: courtyard wall, village information board,
office wall, roadside post, van panel or a character's hands. In TSC preserve those
anchors, ownership, readability and visibility through the relevant shot actions.
Keep unrelated materials out of shots that do not require them.

For commitment forms and similar derived props, use the supplied letter/card as
content and typography authority. Preserve quoted sentences, locality, amounts,
phone numbers and attribution. Do not fabricate obligations, statute citations,
personal data, signatures, approvals or official seals. A title and unsigned blank
signature field can be a production layout, but may not be represented as an
approved official document. Record that distinction. A blank page alone is incomplete
when the script requires a legible document.

Keep exact source masters alongside integrated assets. For small text that an image
model cannot reproduce faithfully, composite source pixels deterministically and
record the transform, or leave text-review pending and block readable final use.
Do not claim reference-image generation guarantees exact text or video persistence.
Conflicting templates (wrong phone/locality/topic) stay archived unchanged; make
new explicitly tracked derivatives using the script and confirmed original text,
or ask if the conflict cannot be resolved. Never overwrite the supplied original.

Before final_prevideo, run validate-material-integration.cjs and include its result
in the release gate. File/hash checks do not prove visible integration: humanReview
must confirm placement and exact required text. Pending/rejected binding blocks
final approval. A project with no supplied materials records applicable:false and
an explicit reason; legacy projects are marked pending migration, not silently passed.

## Portable Release Contract

Every future Auto release must include all modules and locally referenced resources,
tools/plugins/providers/agents/commands, pinned dependencies, runtime installers or
redistributable runtimes, licenses/notices, SHA-256 inventory, offline tests and an
installer which verifies hashes before modifying the destination. Do not ship user
credentials, provider keys, login state, generated customer assets or project history.

Auto D packages a Windows x64 Node/Bun runtime and optional LibTV executable for this
user's machines, the direct image plugin, eight internal skill modules and the
standalone image helper skill instructions used by its route interface. Installation
backs up replaced skill/runtime/command files and never overwrites the host's global
provider configuration or unrelated plugins. Test clean installation in a path with
spaces. Missing platform/runtime/auth requirements must be stated accurately.

The receiving machine still needs a compatible OpenCode host, provider credentials,
network access for paid calls and explicit optional video authorization. Do not ship
or claim to ship a language model. LibTV login is performed separately on the target.

Prefer the currently user-selected route. Defaults never outrank explicit stx. Keep
stx 1K and automatic quality constraints and the no-silent-retry/provider-switch rule.
